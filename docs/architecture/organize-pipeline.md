## The flow

This is the core flow; understand it before touching anything under `lib/services/ai/` or `lib/widgets/ai/`.

1. **Trigger** — `_organize()` in [home_screen.dart](../../lib/widgets/home/home_screen.dart). An empty multi-selection means "the whole folder"; a non-empty one restricts the scan.
2. **Hint** — `showTitleHintDialog` collects an optional canonical title and a movie/series/auto hint.
3. **Task** — `TaskService.startAnalyze(...)` mints an `AiCancelToken`, inserts a running task, and fires `AiService.analyzeFolder` unawaited. The Tasks tab badge tracks `runningCount`.
4. **Analyze** — `AiService.analyzeFolder` walks the tree (**capped at 400 files**, dotfiles skipped) and hands it to [organize_agent.dart](../../lib/services/organize/organize_agent.dart). Code does everything that has a right answer: `FilenameParser` reads season / episode / year / language tokens, `Grouping` puts one title's videos and their companions (subtitles, artwork, NFOs) in one group, and `JellyfinNaming.plan` spells every path. The model decides only what a group *is* — title, movie or series, year, season, episode offset — through tools (`list_groups`, `list_group_files`, `read_existing_nfo`, `submit_group`, `split_group`, `mark_unsure`), so a 26-episode series is one decision rather than 26 paths to spell identically. Each submission's reply lists the paths it produced and any file it could not place, which is how a wrong season gets corrected before the preview. A large folder is decided in **batches** of at most 12 groups (fewer when the context window is small), each a fresh session seeded with a table of the titles decided so far (`find_decided` looks up the rest), so a session's context does not grow with the folder. A batch that throws is retried once, then its groups are marked failed and the rest go on; an `erratic` batch is not retried. The Tasks card shows the fraction of groups decided, and the finished task reports counts (decided, remembered, to review, failed).
5. **Provider** — `OpenAiProvider` (`/chat/completions`) or `GoogleGenAiProvider` (`:generateContent`), both through `AiHttp.withRetry` on the cancel token's client. `OpenAiProvider` **streams** and times out on *silence*, not duration — 10 min for the first event (model load + prompt processing), 2 min between events — and never retries a timeout. A 27B model on LM Studio took 88 s for thirty files, so the old 120 s total failed any real folder, and each retry restarted a generation the server was still running; closing the stream is also what makes a local server stop generating on cancel. A body that is not an event stream is parsed as ordinary JSON, and `stream_options` is dropped if refused. `GoogleGenAiProvider` is not streamed but follows the same rule: 10 min for the whole generation, never retried, because `Future.timeout` does not close the socket and a retry would start a second generation beside the one the server is still running and bill for both. It asks Gemini for no reasoning the same way `OpenAiProvider` does — `thinkingConfig.thinkingBudget: 0` → `thinkingLevel: "low"` (Gemini 3's replacement, whose floor is "low") → nothing (2.5 Pro cannot stop thinking) — stepping on a 400 that names the field *and* on a reply that reasoned anyway, since a relay drops an unimplemented `thinkingConfig` silently. Its `completionTokens` is `candidatesTokenCount + thoughtsTokenCount`: Google reports thinking beside the answer, never inside it. A `promptFeedback.blockReason`, or any `finishReason` other than `STOP` / `MAX_TOKENS`, throws and discards whatever text arrived — a blocked answer is a failure, not an empty reply, and returning it made the agent loop read a moderation hit as "the model stopped calling tools". The check is an allow-list because the request-fault reasons (`MISSING_THOUGHT_SIGNATURE`, `UNEXPECTED_TOOL_CALL`, `TOO_MANY_TOOL_CALLS`, `MALFORMED_RESPONSE`, `OTHER`) arrive with HTTP 200 too and keep growing. `MAX_TOKENS` is a real answer, cut short, and `ChatResult.truncated` already says so. The OpenAI-compatible side does the same for `finish_reason`: `content_filter` / Zhipu's `sensitive` throw as filtered, `network_error` throws as `AiNetworkException`, `model_context_window_exceeded` counts as truncation; an `error` object or MiniMax's non-zero `base_resp.status_code` in a 200 body is reported as the account error it is, and `content` sent as a list of `{type: text}` parts (relays mirroring a backend) is read rather than dropped. The Google key goes in `x-goog-api-key`, never `?key=`. `complete`'s JSON mode (tool-calling `chat` has none) steps down `json_object` → a permissive `json_schema` → none when a 400 names `response_format` (LM Studio accepts only `json_schema`), and the accepted mode is cached per endpoint + model. An OpenAI-compatible profile needs no API key (`AiProviderTypeX.requiresApiKey`); a blank key sends no `Authorization` header at all.

   **`/v1` is appended only to a bare origin.** `http://localhost:1234` is what LM Studio, Ollama and llama.cpp print at startup and what users paste; a URL that already carries a path is left exactly as typed, because a relay routes below its own prefix (`…/api/openai`) and Azure below a deployment name, and appending a version segment there is a 404 whose cause is invisible.

   **A transport failure is never rendered by interpolating the exception.** `package:http` puts the request URL in every `ClientException` it raises, and Google's API used to carry the API key in that URL's query string (it now goes in `x-goog-api-key`), so `'Network error: $e'` printed the key into the settings page and any SnackBar. `AiHttp.describeTransportError` reports the cause alone, and those failures throw `AiNetworkException` — a subclass that marks "the endpoint never answered", which is what lets `probeTools` tell a blip from a verdict.

   **The per-server memories** (accepted JSON mode, refused fields, which way of turning reasoning off took, `max_completion_tokens`) are keyed by provider | base URL | model | *hash of the key*. Two profiles can reach one endpoint through different credentials — a personal and a work account, a gateway that routes by token — and what one was refused says nothing about the other.
6. **Plan** — `OrganizeState.buildPlan` turns the decisions into `OrganizeAction`s. Confidence `< 0.6` → `ActionStatus.needsReview`, and so is every file of a group the model marked unsure or never decided, every file the naming rules could not place, and both of two files planned onto one path: they still appear in the preview rather than silently dropping out of it. A file already at its Jellyfin path gets no action. A run that decides no group at all throws, rather than producing a preview of nothing but flagged rows.
7. **Preview — this is the only dry-run and the only gate.** The AI panel's button says *Preview*, not *Apply*. `OrganizePreviewDialog` lets the user edit `action.target` in place and toggle the undo checkbox, and returns `({bool apply, bool backup})`. Cancel means nothing touched disk.
8. **Apply** — `ApplyController.start()` loops the plan honoring pause/stop, **skipping `needsReview` actions entirely**, calling `applyOrganizeAction` per action.
9. **History** — iff `backup` and at least one move succeeded, a manifest is written for undo.

**Non-obvious invariants:**

- **Only one plan exists app-wide.** A second `analyzeFolder` nulls the current plan immediately — concurrent analyze tasks are last-writer-wins.
- **`AiConfig.contextWindow` is a budget, not a server setting.** Compatible servers fix the context when the model is loaded and accept nothing per request, and local ones do not reject an oversized prompt — they silently drop its front, system prompt first. The app can only send less: every agent tool pages its results, and `AgentRuntime.trimHistory` shrinks the oldest tool results once the history nears the window, estimating through `TokenBudget`, which over-estimates on purpose (three ASCII characters per token, one token per other character). Null means no trimming. The ceiling also comes down by the tool schemas (`AgentRuntime` charges them as `overhead`, since they ride on every request but live outside `messages`) and by the reply's reserve: the window has to hold the prompt *and* the answer.
- **The Settings connection test is a real completion** (`AiConnectionCheck`), not `GET /models` — listing models passed against LM Studio while every generation request was being rejected. `AiProvider.detectLimits()` runs alongside it and reads the *loaded* context where a server exposes one (llama.cpp `/props`, LM Studio `/api/v0/models`, Ollama `/api/ps` + `/api/show`, vLLM / OpenRouter `/v1/models`, Google `models/{model}`), preferring it over a model's maximum. The result is shown beside the fields and only applied on the user's click.
- **Sampling comes from per-family presets** ([sampling_presets.dart](../../lib/services/ai/sampling_presets.dart)). The list is ordered and the first match wins, so a more specific family must precede any family whose pattern also matches it (`qwen3.8` before `qwen3`, `deepseek-r1` before every `qwen`). Every row cites the model card; a family with no published values is deliberately absent, because an invented preset looks authoritative. A preset's values are sent **explicitly, neutral ones included** — servers fill gaps with their own defaults (llama.cpp `min_p 0.05`; Ollama forces `temperature` / `top_p` to 1.0 when missing) — and a field a server refuses by name is dropped and remembered per endpoint + model. A stored `temperature: 0.2` reads as unset (it was the old fixed default, not a choice); saves now use `temperature_override`.
- **Reasoning is off by default** (`AiConfig.thinkingEnabled`). No single field turns it off on every server, and several servers silently ignore the ones they don't know, so `OpenAiProvider` tries `chat_template_kwargs.enable_thinking` → `reasoning_effort: "none"` → Qwen3's `/no_think` in order (Ollama's `/v1` skips the first) and judges each by whether the reply **still reasoned**, never by the absence of an error. The connection test walks those ways; if none takes, settings says so instead of pretending. That ladder is for local servers: on a cloud platform each step is a paid request and the platform documents its own switch, so `ThinkingDialect` ([thinking_dialect.dart](../../lib/services/ai/thinking_dialect.dart)) recognises Zhipu and DeepSeek (`thinking: {type}`) and DashScope (`enable_thinking`) by host and sends that field, both ways, with no ladder — Zhipu lets `chat_template_kwargs` through unread and drops `reasoning_effort: "none"` on GLM-4.x, and DashScope's commercial Qwen never reasons without `enable_thinking: true`.
- **`backup` does not copy anything.** It gates whether an undo manifest is recorded. The name is a misnomer kept for the UI string.
- **`OrganizeAction.target` is deliberately mutable** so the preview dialog can correct the model in memory. This keeps every disk write behind `ApplyController`.
- **The model never writes or names a path.** It points at groups by id and at files by number; `source` is the scan's own relative path and `target` comes from `JellyfinNaming`, so nothing the model says can aim a move outside the folder. Keep new organize tools to that contract.
- **Organizing remembers, keyed by fingerprints** (path + size + mtime, [organize_workspace.dart](../../lib/services/organize/organize_workspace.dart)). A group's decision is saved the moment it is made, so a cancelled or failed run resumes with only the undecided groups; a group changed by `split_group` is never saved, since its files no longer match its fingerprint. Only an *applied* preview's corrections are remembered (`AiService.rememberEdits`) — cancelling means they were never the user's decision — under the file's fingerprint both where it was and where it went, and they win over any decision on the next run. Anything that changes a fingerprint (a re-encode, a cross-volume move that resets mtime) is a miss, never a stale hit, and an unreadable cache is an empty one.
- **Every AI task needs a model that calls tools — there is no single-shot fallback.** The connection test probes it (`AiConnectionCheck.probeTools`, asked twice because small models sometimes answer in prose once). The answer is stored on the profile as `ToolSupport`, keyed by provider | endpoint | model, so it goes stale when any of those changes. A never-tested profile is probed on first use by `AiService.ensureTools`, and a model known not to call tools disables Organize and the scrape panel's LLM buttons.

  **The probe has three outcomes, not two.** A server that refuses the `tools` field has answered the question (`unsupported`); a request that never arrived has answered nothing (`inconclusive`) and is recorded nowhere. Collapsing the two wrote one dropped connection to the profile as a permanent "this model does not call tools", which stays until a human re-runs the test in Settings — and tells the wrong story to someone whose Wi-Fi went down. `ensureTools` surfaces the transport failure instead.
- **Cancellation works by closing the token's own `http.Client`**, so cancellable requests must not use the shared `AiHttp.client`. A socket close surfaces as a generic `ClientException` and is re-mapped to `AiCancelled`.
- `AiService.updateConfig` is called from a widget `build()`, so it early-returns when unchanged and defers `notifyListeners` via a post-frame callback. Breaking either causes "setState() during build".

## Agent runtime

[agent_runtime.dart](../../lib/services/agent/agent_runtime.dart) is the one tool loop that organizing, recipe learning and direct extraction all run through. A task supplies its tools, its own state and a completion check; the protocol obligations live in the loop, once:

- **Every tool call gets a reply.** A cancel mid-round answers the calls it skipped with `notRunResult` before throwing — a history with an unanswered call is rejected on every later turn.
- **A bad call is text, not an exception.** A tool throws `ToolError` phrased as the *next step* ("There is no group "g7". Call list_groups…"), and the model gets another round. Three rounds in a row of nothing but failed calls end the run as `erratic`: a model that cannot drive the tools only burns tokens. A round whose reply hit the output limit (`finish_reason: length`) does not count: its arguments were cut off, which reads exactly like bad JSON. Two such rounds in a row, or a cut-off reply with no tool call, end the run as `truncated`, and the user is told to raise the maximum output rather than to change models.
- **A round that leaves the task done ends the run** (unless `stopWhenDone: false`, which direct extraction uses so the model may keep adding fields), so a small model does not spend a turn announcing it has finished. A model that stops early is nudged at most twice, and **the nudge is retracted once it has been sent** — along with the model's own "I am finished" turn. A reminder left in the history becomes a standing instruction, and organize's carries state ("still undecided: g3, g7") that is wrong by the next round; retracting only the reminder would strand that assistant turn, and then put two assistant turns in a row once the model resumed calling tools, which Gemini rejects.
- **`trimHistory` shrinks old tool results; it never removes a message**, for the same pairing reason.
- Nothing relies on a forced `tool_choice` — some servers accept only `auto` while reasoning.

Underneath, `AiProvider.chat` accumulates OpenAI `tool_calls` fragments by index (a repeated id or name fragment is ignored, since some servers resend them), passes a reasoning field back only on assistant messages that carry tool calls, and keeps Gemini's raw model parts verbatim, because their thought signatures are what the next turn is validated against.
